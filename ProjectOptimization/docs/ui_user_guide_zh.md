# UI 使用指南

## 1. 启动

```bash
python scripts/tools/run_qt5_app.py
```

## 2. 界面说明

- 顶部状态卡：环境状态、数据状态、模型状态、任务状态。
- 四个功能页签：
  1. 环境与数据
  2. 训练
  3. 测试
  4. 推理
  5. 消融
- 右侧日志观测区：简易关键日志（便于快速看状态）。
- “详细日志窗口”：完整输出，单独弹窗查看训练/推理细节。
- 推理页包含：
  - 内嵌视频画面区（实时显示帧）
  - 目标结果表格（ID/检测置信度/动作标签/动作置信度/位置）
  - 测试视频目录显示与快捷打开
  - 推理输出目录显示与快捷打开

## 3. 推荐使用流程

1. 进入“环境与数据”页，点击“环境检测并自动修复”。
2. 观察“数据状态”中的关键点一致性提示（V与layout必须匹配）。
3. 进入“训练”页，先选择训练方案（17点/18点），再选择模式（预训练初始化/微调）并开始训练。
4. 进入“测试”页，执行模型快速检查。
5. 进入“推理”页，选择视频并开始推理。
6. 推理过程中可在推理页直接查看画面与目标表格变化。
7. 如需标准化消融，进入“消融”页生成 `ablation_plan.md/csv` 与命令模板。

## 4. 模型下拉框默认策略

- YOLO下拉框：优先 `models/yolo/custom/yolo_pose_best.pt`。
- 若已完成消融训练，YOLO 下拉也可识别 `outputs/eval/ablation/**/weights/*.pt` 产物。
- ST-GCN下拉框：优先已存在的 `best.pt`（优先 out17，其次 out3）。
  - 若 `best.pt` 不存在，默认选择可用的真实权重（如最新 `epoch*_model.pt`）。
- 顶部支持“显示全部模型版本”开关：
  - 关闭（默认）：精简模式，仅展示 best/预训练/最新epoch。
  - 开启：完整模式，显示全部 epoch 版本（含消融目录下多实验权重）。

## 5. 训练方案与关键点布局（17/18）

- 训练页将“训练方案”与“关键点布局/训练配置”联动：
  - 17关键点（yolopose） -> `configs/train/train_stgcn_out17.yaml`
  - 18关键点（openpose） -> `configs/train/train_stgcn_out3.yaml`
- 初始化模型会按方案自动选择同布局权重。
- 若手动选择了不兼容权重，启动前会弹窗拦截。
- 训练页“初始化策略”会给出实时提示：
  - 继续预训练（保留分类头）
  - 迁移初始化（自动忽略 `fcn`）
  - 不兼容风险提示（布局/类别数不匹配）

## 6. 日志与排错

- UI日志文件：`logs/run_logs/ui_app.log`
- 若报“模型不存在”：先检查 `models/` 对应路径。
- 若报“数据缺失”：先检查 `data/stgcn_dataset_out3/` 文件是否完整。
- 推理输出默认目录：`outputs/infer/`。
- 测试视频默认目录：`src/ultralytics-main/dataset/GCNData/BaseballPitch/`。

## 7. 继续训练建议

- 预训练不够：可继续使用“预训练初始化”，并选择已有同布局权重继续。
- 微调续训：选择“微调训练”，初始化模型选择上次产物（`best.pt` 或 `epoch*_model.pt`）。
- 从头训练：初始化模型选择“从头训练（不加载权重）”。

## 8. 消融实验（规范模板）

- 入口：UI 的“消融”页。
- 可选择主题：`YOLO模块消融（ADown/DyRFAUp/SCSA）`。
- 可通过下拉/选择框直接设置：模型YAML、数据YAML、epochs、device（不必手改命令文件）。
- 输出目录也支持可编辑下拉（可手输/可选择目录，自动记录最近使用）。
- 当前主题支持 `POSE/DETECT/CLS/SEG/OBB`，但模型YAML与数据YAML任务类型必须一致。
- 非兼容组合会显示红色提示，并自动禁用“生成规范模板/开始批跑消融”按钮。
- 若为 Pose 任务，还会额外校验关键点数与 17/18 数据方案一致性。
- 即使从项目外目录手动选择YAML，也会执行同样的兼容性检测（任务类型、关键点数、17/18方案）。
- 自动扫描范围默认是项目内：
  - 模型：`src/ultralytics-main/ultralytics/cfg/models/`
  - 数据：`src/ultralytics-main/ultralytics/cfg/datasets/`
- 若希望“自动扫描就能看到”，请把新增YAML放到以上目录；放在外部目录也可手动选择，并会进入“最近使用”。
- 点击“生成规范模板”后，会在输出目录生成：
  - `ablation_plan.md`（实验矩阵与结果记录模板）
  - `ablation_plan.csv`（结构化实验清单）
  - `run_commands.txt`（命令模板）
- 补全 `run_commands.txt` 后，点击“开始批跑消融”可自动逐项执行。
- 运行中可点击“停止批跑/任务”立即中止当前消融子进程。
- 批跑过程中会实时转发子进程日志到UI；若阶段性无输出，会周期打印“运行中心跳”避免误判卡死。
- 批跑完成后会生成：
  - `ablation_results.csv`
  - `ablation_results.md`
  - `run_logs/*.log`（每个实验一份日志）
- 训练权重由命令中的 `project` 与 `name` 决定；默认在：
  - `outputs/eval/ablation/<实验名>/weights/best.pt`
  - `outputs/eval/ablation/<实验名>/weights/last.pt`
- 这些权重可直接用于后续测试/推理，也可作为下一轮消融的起点。
- 建议统一控制变量：数据、训练轮次、学习率策略、随机种子保持一致。
